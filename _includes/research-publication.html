{% comment %} One "selected publication" entry on /research/. Driven by front matter on the _publications/ document: selected: true summary: > # plain-language description, optional; ... # falls back to `excerpt` Figures live in images/ and are referenced by bare filename. Each figure is either WIDE — spanning the entry, stacked above the summary, for long horizontal figures — or not, in which case it goes in a column on the left with the summary running alongside it. Single figure: figure: some-figure.png figure_alt: "..." # optional figure_caption: "..." # optional figure_wide: true # optional, default false Several figures (mirrors the `links:` list-of-maps pattern) — can be combined with `figure:` above, in which case that one comes first within its slot: figures: - src: evolution.png wide: true # optional, default false alt: "..." # optional caption: "..." # optional - src: sdBs_v2.png # not wide: sits left of the summary So an entry can mix both: a long figure across the top, a tall one beside the text. `width:` tunes how much room a figure takes — any CSS length, by eye, since the right value depends on the figure's proportions and how much you wrote. What it sets depends on the slot (see _sass/layout/_research.scss): figures: - src: sdBs_v2.png width: 55% # side: the column, default 35% - src: evolution.png wide: true width: 70% # wide: the figure itself, default 100%; # anything less is centered in the entry Side figures share one column, so the first `width:` among them sets it and the rest are ignored — they stack at that column's width. `figure_width:` at the top level sizes whichever slot the `figure:` above lands in: the wide figure when `figure_wide: true`, otherwise the side column, where it takes precedence over any per-figure `width:`. It never sizes both.
